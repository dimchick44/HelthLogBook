# Подключение почтового ящика по IMAP

IMAP-коннектор — дополнительный источник рядом с пересылкой. Он читает **только входящие** письма, ничего не удаляет и не отправляет. Сервер забирает новые письма по UID, вложения попадают в общий inbox.

## 1. Что нужно от почтового провайдера

Нужен **пароль приложения** (app password), а не основной пароль от аккаунта. Обычно он создаётся в настройках безопасности после включения двухфакторной аутентификации.

| Провайдер | Хост | Порт | Примечание |
|---|---|---|---|
| Gmail | `imap.gmail.com` | 993 | включить IMAP в настройках, создать app password |
| Outlook / Hotmail | `outlook.office365.com` | 993 | базовый IMAP может быть отключён организацией |
| Яндекс | `imap.yandex.ru` | 993 | включить IMAP, создать пароль приложения |
| Mail.ru | `imap.mail.ru` | 993 | создать пароль для внешнего приложения |
| Корпоративный | уточнить у админа | 993 | нужен доступ по IMAP |

Если провайдер требует OAuth и не выдаёт app password, IMAP-подключение не заработает — используйте пересылку на `u-<token>@in.<домен>`.

## 2. Создать подключение

```powershell
curl.exe -X POST http://127.0.0.1:8000/v1/mail/accounts/imap `
  -H "Authorization: Bearer <access_token>" `
  -H "Content-Type: application/json" `
  -d "{\"address\":\"you@gmail.com\",\"host\":\"imap.gmail.com\",\"port\":993,\"username\":\"you@gmail.com\",\"password\":\"app-password\",\"use_ssl\":true,\"folder\":\"INBOX\"}"
```

Ответ не содержит пароль. В базе он хранится зашифрованным (Fernet).

## 3. Запустить синхронизацию

```powershell
curl.exe -X POST http://127.0.0.1:8000/v1/mail/accounts/<account_id>/sync `
  -H "Authorization: Bearer <access_token>"
```

Ответ:

```json
{
  "account_id": "…",
  "kind": "imap",
  "fetched": 3,
  "accepted": 2,
  "duplicates": 1,
  "skipped": 0,
  "inbox_items": 2,
  "last_uid": 142,
  "last_sync_at": "2026-11-19T18:20:00Z"
}
```

Повторный вызов не перекачивает старые письма: сервер помнит `imap_last_uid`.

## 4. Как это работает

1. Сервер подключается по IMAP (`IMAP4_SSL` по умолчанию).
2. Ищет письма с `UID > imap_last_uid` в выбранной папке.
3. Забирает тело через `BODY.PEEK[]` — письмо **не помечается прочитанным**.
4. Передаёт письмо в тот же конвейер, что и пересылку: MIME-разбор, allowlist, правила, дедупликация, вложения в inbox.
5. Сдвигает `imap_last_uid` и сохраняет `last_sync_at`.
6. За один вызов обрабатывается не больше `MEDARCHIVE_IMAP_SYNC_LIMIT` писем (по умолчанию 50).

## 5. Настройки

```dotenv
MEDARCHIVE_SECRET_ENCRYPTION_KEY=change-me-stable-key
MEDARCHIVE_IMAP_SYNC_LIMIT=50
MEDARCHIVE_IMAP_TIMEOUT_SECONDS=20
```

`MEDARCHIVE_SECRET_ENCRYPTION_KEY` задаёт ключ шифрования паролей. Если он не задан, ключ выводится из `MEDARCHIVE_JWT_SECRET`. В production задайте отдельный стабильный ключ: после его смены сохранённые пароли перестанут расшифровываться, и ящики нужно будет подключить заново.

## 6. Ограничения текущей версии

- Синхронизация выполняется прямо в HTTP-запросе. Для регулярного опроса позже добавим фоновый воркер.
- OAuth (Gmail API, Microsoft Graph) не поддерживается — только пароль приложения.
- Папки, кроме указанной, не сканируются; по умолчанию `INBOX`.
- Письма не помечаются прочитанными и не удаляются.
