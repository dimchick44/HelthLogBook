# ADR-003. Локально-первое MVP: галерея и файлы

## Контекст

Аудитория — Россия. Часть зарубежных сервисов недоступна, ограничена или требует зарубежной карты. Собственный сервер (VPS, Postgres, S3, SMTP) не хостим. Допустимый максимум — Supabase и Vercel, и то как опция, а не как обязательная зависимость.

При этом распознавание медицинских документов должно выполняться полностью на устройстве: без облачных OCR, LLM и внешних AI-API.

## Решение

MVP строится как **offline-first приложение**:

- Источник документов на старте — **галерея и файлы** (PDF, JPEG, PNG, HEIC).
- Почта (IMAP/пересылка) переносится на следующий этап.
- Все документы, оригиналы, результаты OCR и метаданные хранятся **локально**:
  - SQLite через Drift;
  - файлы в приватной папке приложения;
  - секреты — в `flutter_secure_storage`.
- OCR — Tesseract 5 с `rus.traineddata`, офлайн.
- Классификация типа документа и извлечение полей — локальные правила, словари, regex; позже — компактная модель на ONNX.
- Supabase — **необязательный** бэкап/синхронизация, включается флагом. Без аккаунта приложение полностью работоспособно.
- Vercel в MVP не используется. Допустим позже для лендинга или веб-админки.
- Backend на FastAPI остаётся в репозитории как прототип и референс, но не является частью MVP-поставки.

## Последствия

- Приложение работает без интернета и без регистрации.
- Нет синхронизации между устройствами в MVP — только ручной экспорт/бэкап.
- Размер приложения растёт: `rus.traineddata` ~20 МБ, Tesseract ~10–15 МБ; бюджет ≤ 120 МБ AAB остаётся достижимым.
- Google Play не используется для оплаты и может быть недоступен для публикации из РФ — планируем APK и RuStore.
- Supabase нельзя делать обязательным: если сервис замедлится или будет ограничен, приложение продолжает работать.
- Все сетевые интеграции — за feature-флагом и с явным согласием пользователя.
